1. **JSONL：线性落盘，树形解释**

“追加式”描述存储方式：新事件只写到文件末尾，旧记录不会因继续对话或 compaction 被改写、删除。

“可分支”描述逻辑结构：每条 entry 用 `parentId` 指向父节点，因此文件的行序虽然是线性的，节点关系却是一棵树。

用户回到旧节点继续对话时：

- 文件不会截断旧节点之后的记录，而是在末尾追加新 entry，其 `parentId` 指向该旧节点，于是产生一个新分支；原分支仍在。
- 模型上下文会切换到新分支的叶子：沿父指针回溯，只重建这条活动路径，而不是读取整个 JSONL。
- 若路径上发生过 compaction，模型看到的是“摘要 + 保留的近期消息”。完整事件仍在文件中，但不等于当前模型实际看到的上下文。

可把 JSONL 想成“只增不改的节点仓库”，把模型上下文想成“从当前叶子投影出来的一条路径”。

2. **Turn 是任务级边界，Step 是模型调用级边界**

Turn 从用户输入开始，到模型返回一个不再要求调用工具的最终回复结束。其间每次“请求模型并处理其工具调用”的循环构成一个 Step。

以“先读文件、再改文件、最后回答”为例：

- 用户提出任务，Turn 开始。
- Step 1：把当前上下文发给模型；模型请求读取文件；宿主执行读取并把结果送回。
- Step 2：带着读取结果再次请求模型；模型请求修改文件；宿主执行修改并返回结果。
- Step 3：再次请求模型；模型确认结果并给出最终答复，不再调用工具，Turn 结束。

因此，工具调用不是新 Turn；它推动同一个 Turn 进入下一次模型循环。若模型一次回复同时请求读取多个互不依赖的文件，这些并行调用仍可属于同一个 Step。

3. **三种扩展位于不同层**

- **Extension**：宿主运行层。它是运行中的 TypeScript 模块，可监听生命周期、拦截或修改工具调用、注册工具和命令、操作 UI、保存状态，并拥有宿主进程权限。
- **Skill**：模型指导层。它主要是模型读取的 Markdown 工作指引，影响模型如何判断和行动。
- **prompt template**：用户输入层。它由用户主动展开，把预设提示内容放入对话。

危险命令拦截器若做成 Skill，本质只是告诉模型“不要这样调用”。这依赖模型正确读取、理解并始终遵守；指导还可能在有损 compaction 后弱化或遗漏。它并未站在工具执行路径上强制检查。

Extension 则能在工具调用真正执行前拦截或修改请求，所以可把规则做成程序化的执行边界。当然，保证仍取决于扩展代码本身正确且可信。
