```text
Session：跨多次 run 保存对话历史
   ↓ 提供上下文 / 接收新历史
Runner：执行和编排一次 run
   ↓ 当前该由谁处理
Agent：描述角色、指令、模型、工具和 handoff
   ↓
Model：真正执行一次推理
```

核心区别是：

- **Agent 是配置/角色**：规定“用哪个模型、遵循什么指令、能调用哪些工具、能转交给谁”。它自己没有执行循环。
- **Runner 是执行引擎**：真正驱动流程。它调用当前 Agent 配置的模型，执行工具，把工具结果送回模型，并处理 handoff；一次 `run` 中可能发生多次模型调用。
- **Session 是持久化上下文层**：不属于某个 Agent，也不是 Runner 本身。它通常在调用 `run` 时交给 Runner，让 Runner 在本次运行前读取历史、结束后追加新历史。

时间尺度也不同：

```text
Session
├── Run 1 → Runner 驱动 Agent A → 若干模型/工具轮次
├── Run 2 → Runner 驱动 Agent A → handoff 到 Agent B
└── Run 3 → Runner 继续利用此前历史
```

所以可以简单记成：

> **Agent 定义“谁来做、怎么做”；Runner 负责“把它跑起来”；Session 负责“跨多次运行记住发生过什么”。**

另外，`RunResult` 只是某一次运行的结果快照；它可以包含这次运行的历史和状态，但不等同于可跨运行保存的 Session。
