不是两个都在“跑模型”。按 `source.md` 的定义，它们分别是配置与执行：

```text
Session（跨多次 run 的持久对话历史）
   │
   ▼
Runner.run(起始 Agent, 新输入, Session)
   │
   ├─ 调用当前 Agent 指定的模型
   ├─ 执行工具，把结果送回下一轮模型调用
   ├─ 处理 handoff，切换当前 Agent
   └─ 得到最终输出，结束本次 run
```

- **Agent**：声明“谁来做、怎么做”。它携带 instructions、model、tools、handoffs、输出类型，但自己不执行。更像一份角色与能力配置。
- **Runner**：负责“真正把流程跑起来”。它维护循环、调用模型、执行工具、处理 handoff、guardrails 和 tracing。一次 run 里可能调用模型很多轮，也可能依次经过多个 Agent。
- **Session**：处于跨 run 的会话状态层。Runner 在运行前从 Session 取历史，运行后把新增历史写回去。它不属于某个 Agent，也不等于单次运行返回的 `RunResult`。

可以用一句话概括：

> Agent 是“执行规格”，Runner 是“执行引擎”，Session 是“跨执行保存的记忆”。

之所以分开，是为了让同一个 Agent 配置可以被不同 Runner 配置执行，也让同一个 Runner 能执行不同 Agent；同时 Session 可以独立决定是否持久化和复用。例如：

```text
同一个 Session
  ├─ run #1：客服 Agent → 最终回答
  └─ run #2：客服 Agent → handoff → 退款 Agent → 最终回答
```

这里 `run #2` 内部换了 Agent，但仍可以沿用同一个 Session 的对话历史。换句话说，**Session 通常包住多次 run，而一次 run 又可以包含多个 Agent turn**。
