不是两者都在“跑模型”。更准确地说：

- **Agent 定义怎么跑**：模型、指令、工具、handoff、输出类型。它像一份“角色与能力配置”，自己不会启动执行。[source.md:5](/private/var/folders/sz/cc03_p510f55yvxmgytgww9r0000gn/T/xunxun-v2-7s8tqv_1/work/agents-agent-runner-session/source.md:5)
- **Runner 负责真的跑起来**：调用模型、执行工具、把工具结果送回模型、处理 handoff，并判断什么时候结束。[source.md:7](/private/var/folders/sz/cc03_p510f55yvxmgytgww9r0000gn/T/xunxun-v2-7s8tqv_1/work/agents-agent-runner-session/source.md:7)
- **Session 保存跨 run 的对话历史**：让下一次运行能够接着上一次聊，而不是每次从零开始。[source.md:9](/private/var/folders/sz/cc03_p510f55yvxmgytgww9r0000gn/T/xunxun-v2-7s8tqv_1/work/agents-agent-runner-session/source.md:9)

可以这样看：

```text
Session：跨多次运行的记忆
   │
   ▼
Runner：执行引擎 / 循环控制器
   │ 调用
   ▼
Agent：当前采用的角色、模型与工具配置
   │
   ▼
模型生成 → 工具调用 → 结果返回 → 再次生成
```

为什么要拆成 Agent 和 Runner？因为“做什么、具有什么能力”与“怎样调度执行”是两类变化：

- 同一个 `Agent` 可以放进不同 Runner 环境，例如使用不同的 tracing、guardrail 或模型提供商。
- 同一个 `Runner` 可以执行不同 Agent。
- 一次运行中发生 handoff 时，Runner 不换，**当前 Agent 会换**。
- 这样 Agent 不需要自己处理循环、工具调度、历史装载和可观测性。

`Session` 不是 Agent 的下一层，也不是 Runner 的内部步骤；它是一个与二者协作的**状态存储层**。应用通常把三者组合起来：

```text
应用
├── Agent：任务定义
├── Runner：执行机制
└── Session：跨运行状态
```

还要区别 `Session` 和 `RunResult`：

- `Session`：跨多次 `run` 持久保存历史。
- `RunResult`：某一次 `run` 的结果快照，包括最终输出、最后的 Agent 和本次运行状态。

一句话概括：**Agent 是“演员设定”，Runner 是“导演兼舞台机器”，Session 是“连续剧前情记录”。**
