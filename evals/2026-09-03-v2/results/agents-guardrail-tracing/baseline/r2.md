因为两者解决的是不同问题：

- **Tracing 是可观测性**：记录模型生成、工具调用、handoff 和 guardrail 检查等过程，方便事后调试、审计和定位问题。
- **Guardrail 是执行控制**：在输入、最终输出或工具调用的边界上做判断，并在触发条件时阻止或中止操作。

例如，Agent 准备调用工具执行转账：

- 只有 tracing：你能在记录里看到它为什么转账、调用了什么工具——但钱可能已经转出去了。
- 有 tool guardrail：可以在工具真正执行前检查金额、收款人或授权状态，不符合规则就拦截。

`source.md` 里最关键的一句就是：**“Recording an event does not itself block it.”** 记录事件不等于阻止事件。

二者实际上互补：

1. Guardrail 降低事故发生的概率和影响。
2. Tracing 证明 guardrail 是否被执行、为何触发，并帮助发现规则遗漏。
3. 根据 tracing 中的误拦截和漏拦截，再迭代 guardrail。

还有一个重要细节：并非所有 guardrail 都保证“先检查再执行”。文档提到，并行 input guardrail 虽然延迟较低，但结果返回前 Agent 可能已经消耗 token 或开始工作；如果必须确保任何处理都不能提前发生，就要使用串行检查。
