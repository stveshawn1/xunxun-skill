因为两者解决的是不同问题：

- **Tracing 是“看见和记录”**：记录模型生成、工具调用、handoff、guardrail 检查等过程，主要用于调试、审计、复盘和性能分析。
- **Guardrail 是“判断和阻止”**：在运行链路中检查输入、最终输出或工具调用，并在违反规则时触发 tripwire，阻断或改变执行。

可以类比为：**tracing 是监控录像，guardrail 是门禁和急停按钮**。录像能告诉你事故怎么发生，却不会自动阻止事故。

对 Agent 尤其如此：如果模型准备调用“转账”“删数据”“发送邮件”之类的工具，仅仅把调用记进 trace，副作用可能已经发生。Tool guardrail 则可以在真正执行自定义工具前拦截；input guardrail 可以在处理恶意输入前阻断；output guardrail 可以防止不合规结果交付给用户。

还有一个容易忽略的细节：`source.md` 提到并行 input guardrail 虽然延迟更低，但在 tripwire 返回前，Agent 可能已经消耗 token 或开始工作。如果必须做到“检查通过之前绝不执行”，就要使用串行检查。

所以更准确的关系是：

> Guardrail 提供运行时约束，tracing 提供可观测性和证据。  
> Tracing 能帮助发现并改进 guardrail，但不能代替 guardrail 本身。
