核心区别是：

> **Tracing 负责“看见发生了什么”，guardrail 负责“决定是否允许它发生”。**

`source.md` 明确说，tracing 会记录 run、模型生成、工具调用、handoff、guardrail 等事件，但**记录事件本身不会阻止事件**。

例如 Agent 准备调用工具，把客户隐私发送到外部服务：

- **Tracing**：留下记录——模型生成了哪些参数、调用了哪个工具、工具返回了什么。适合事后排查、审计和改进。
- **Tool guardrail**：在自定义工具真正执行前检查参数；发现隐私后触发 tripwire，阻止调用。它处于执行控制路径上。

可以把二者理解为：

```text
输入 → guardrail → 模型 → guardrail → 工具 → 模型 → guardrail → 输出
                         │
                         └──── tracing 全程记录
```

摄像头能证明门被打开过，但不能代替门锁。Tracing 类似摄像头，guardrail 类似门锁。

两者也有互补关系：

- tracing 帮你发现风险模式、误拦截和漏拦截，从而改进 guardrail；
- guardrail 提供运行时约束；
- tracing 再记录 guardrail 检查了什么、是否触发，供审计使用。

还有一个重要细节：不是所有 guardrail 都保证“先拦再做”。`source.md` 提到，并行 input guardrail 为了降低延迟，会和 Agent 同时运行，因此 tripwire 返回前，Agent 可能已经消耗 token 或做了一些工作。若必须确保敏感输入未经批准绝不进入模型或后续执行，就需要**串行检查**。

所以，即使 tracing 完全透明，仍然需要 guardrail：**可观测性不能自动转化为安全边界。**
