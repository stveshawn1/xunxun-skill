因为两者职责不同：

- **Tracing 是观察机制**：记录模型生成了什么、调用了哪个工具、发生了哪些 handoff。像监控录像，方便事后审计、调试和复盘。
- **Guardrail 是控制机制**：检查输入、输出或工具调用，并在违规时触发阻断。像门禁或断路器。

例如，Agent 准备调用工具删除数据：

- 只有 tracing：你之后能看到“它删除了数据”，但动作已经发生。
- 有 tool guardrail：可以在工具真正执行前拒绝调用。

`source.md` 最关键的一句正是：“Recording an event does not itself block it.”（[source.md](/private/var/folders/sz/cc03_p510f55yvxmgytgww9r0000gn/T/xunxun-v2-c5rsc611/work/agents-guardrail-tracing/source.md:23)）

还有一个容易忽略的区别：即使配置了 guardrail，也不一定及时阻止所有工作。并行 input guardrail 为了降低延迟，会和 Agent 同时运行，所以 tripwire 返回以前，模型可能已经花费 token 或进行了部分工作；需要严格“先检查、后执行”时，应采用串行检查（[source.md](/private/var/folders/sz/cc03_p510f55yvxmgytgww9r0000gn/T/xunxun-v2-c5rsc611/work/agents-guardrail-tracing/source.md:21)）。

因此它们是互补关系：

> guardrail 降低事故发生概率；tracing 让你知道系统实际发生了什么，并帮助改进 guardrail。

简化成一句话：**tracing 回答“发生了什么”，guardrail 决定“是否允许发生”。**
