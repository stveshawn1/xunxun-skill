本质差异不是“谁更专业”，而是**谁拥有接下来的对话控制权和最终责任**。

|---|---|---|---|---|
| 专家 Agent 当 tool | 主治医生请专家会诊 | 始终是 Manager | 一份供 Manager 使用的结果 | Manager 整合后回答 |
| handoff | 转科、转接客服 | 切换成专家 Agent | 专家直接继续处理 | 专家回答，直到结束或再次 handoff |

### 当成 tool

流程大致是：

```text
用户 → Manager → 调用专家 → 专家结果返回 Manager → Manager 综合回答
```

Manager 保留：

- 对话控制权
- 统一口吻和格式
- 跨领域信息整合
- 是否采纳专家意见的判断
- 最终答案责任

适合“**我需要专家提供一块材料**”：

- 写报告时请财务 Agent 算指标
- 请检索 Agent 找资料，再由 Manager 综合
- 同时调用法律、技术、商业 Agent 做比较
- 专家输出需要被裁剪、交叉验证或结构化

### Handoff

流程大致是：

```text
用户 → 分诊 Agent → handoff → 专家 Agent → 专家继续整个对话
```

它不是一次函数调用，而是 Runner 把“当前 Agent”改成专家；后续轮次由专家的 instructions、tools、handoffs 和输出约束主导。[source.md](/private/var/folders/sz/cc03_p510f55yvxmgytgww9r0000gn/T/xunxun-v2-c5rsc611/work/agents-manager-handoff/source.md:13)

适合“**这件事现在应该由专家接管**”：

- 售前识别为退款问题后转给退款 Agent
- 通用助手识别为报税流程后转给税务 Agent
- 专家需要连续追问用户、执行多个步骤
- 后续大部分对话都属于同一专业域

### 最容易选错的几种情况

**1. 看见“专家”就 handoff**

任务虽然需要专业知识，但最终需要多个领域的统一答案。例如旅行规划同时涉及预算、交通、酒店和签证。过早 handoff 给酒店 Agent，酒店视角会接管全局。

这种应优先 agents-as-tools，由 Manager 综合。

**2. 把长期负责者当成一次性 tool**

例如退款 Agent 必须追问订单号、核验付款、解释政策、执行退款。若把它当 tool，容易出现：

```text
Manager 问专家 → 专家说缺订单号
Manager 问用户 → 再调用专家
专家又要重建上下文……
```

这种反复嵌套既浪费 token，也容易丢失领域状态，handoff 更自然。

**3. 忽略最终输出和 guardrail 的归属**

文档指出，输出 guardrail 检查的是“最终产生输出的 Agent”。handoff 后，最终输出者很可能已不是入口 Agent。[source.md](/private/var/folders/sz/cc03_p510f55yvxmgytgww9r0000gn/T/xunxun-v2-c5rsc611/work/agents-manager-handoff/source.md:16)

如果必须由 Manager：

- 统一脱敏
- 统一品牌语气
- 加免责声明
- 验证多个专家结论
- 严格满足固定输出 schema

那么通常应把专家当 tool，或确保这些约束也覆盖 handoff 后的 Agent。

**4. 误以为 handoff 是“调用完自动回来”**

handoff 是控制权转移，不是普通调用栈。专家成为 current Agent 后，不会天然回到原 Manager；要回来，需要显式配置反向 handoff 或其他路由。

**5. 误以为 tool 一定更安全**

tool 模式确实便于 Manager 审核专家结果，但专家作为工具运行时仍可能调用自己的工具、消耗 token 或产生副作用。真正的安全边界仍要靠权限、tool guardrails、审批和幂等设计，不能只靠组合模式。

### 一个够用的判断法

问自己一句：

> 我是在“向专家要一份结果”，还是“把用户交给专家继续服务”？

- 要一份结果 → **Agent as tool**
- 交给专家继续服务 → **handoff**
- 需要多个专家并行、比较、裁决 → **Manager + agents as tools**
- 需要专家连续追问并完整完成领域流程 → **handoff**
- 拿不准时，默认先用 **tool**：控制权更集中，后续再升级为 handoff 通常更容易。
