它们主要都是“启动配置层”，不是运行中的对象。可以这样区分：

| 概念 | 磁盘上的形态 | 作用 | 是运行时对象吗？ |
|---|---|---|---|
| **Profile** | 一个目录，包含 `package.json` 和自己的 `cordis.patch.yml` | 定义要按什么顺序加载 Bundle，并做 Profile 级定制 | 不是 |
| **Bundle** | 一个 npm 包；其 `package.json` 指向一个 Patch 文件 | 提供一组可复用、可分发的默认插件配置 | 不是 |
| **Patch** | 通常是 `cordis.patch.yml` 配置文件 | 描述如何新增、修改或禁用插件条目 | 不是；加载后会被解释执行 |

它们的关系大致是：

```text
Profile 目录
├── package.json
│   └── dsh.profile.bundles:
│       ├── Bundle A（npm 包）──→ Patch A
│       └── Bundle B（npm 包）──→ Patch B
└── cordis.patch.yml             ← Profile Patch
```

启动时，DSH 从空的插件条目列表开始，依次应用：

```text
Bundle A Patch
→ Bundle B Patch
→ Profile Patch
→ Home Patch
→ 命令行覆盖
→ Launcher 覆盖
```

越靠后的层优先级越高。Patch 可以：

- 插入一个插件条目；
- 按条目 `id` 修改其配置；
- 禁用某个条目。

真正的运行时对象出现在组合完成以后：最终插件条目被 Cordis 应用，每次插件应用对应一个 **Fiber**；插件提供的能力则可能成为 **Service**，由 `Context` 解析和访问。

一句话概括：

> **Profile 是启动方案目录，Bundle 是可复用的 npm 配置包，Patch 是修改插件条目列表的配置文件；Fiber 和 Service 才是运行时对象。**
