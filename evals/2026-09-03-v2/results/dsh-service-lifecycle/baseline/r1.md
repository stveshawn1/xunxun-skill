核心是：`ctx` 不是普通对象，而是一个“服务容器”的 Proxy。`super(ctx, 'llm')` 也不是简单执行 `ctx.llm = this`。

大致流程如下：

```text
LLM 服务插件
  super(ctx, 'llm')
        │
        ▼
注册服务：名字 "llm" → 当前实例
        │
        ▼
Cordis 的服务注册表
        │
        ▼
其他插件读取 ctx.llm
        │
        ▼
Context Proxy 查询注册表，返回该实例
```

### `super(ctx, 'llm')` 做了什么

`Service` 基类内部的关键代码是：

```ts
self.ctx.reflect.provide(name, self, this[symbols.check])
```

所以：

```ts
class LLMService extends Service {
  constructor(ctx: Context) {
    super(ctx, 'llm')
  }
}
```

相当于向 Cordis 声明：

> 当前 Fiber 提供一个名为 `llm` 的服务，其值是这个 `LLMService` 实例。

Cordis 会在服务注册表中保存类似的信息：

```ts
{
  name: 'llm',
  value: llmServiceInstance,
  fiber: providerFiber
}
```

此时并没有真的在 JavaScript 对象上添加一个普通的 `llm` 字段。

当消费者写：

```ts
ctx.llm
```

`Context` 的 Proxy `get` trap 会拦截这次读取，查找当前作用域中名为 `llm` 的有效服务，然后返回注册的实例。因此效果看起来像：

```ts
ctx.llm === llmServiceInstance
```

但本质上是动态服务解析。相关实现见 [service.ts](https://github.com/deepseek-ai/deepseek-harness/blob/master/vendor/cordis/src/service.ts) 和 [reflect.ts](https://github.com/deepseek-ai/deepseek-harness/blob/master/vendor/cordis/src/reflect.ts)。

### `inject: ['llm']` 做了什么

它不是把某个对象“注入”到 `ctx` 中，而是声明：

> 这个插件必须依赖 `llm` 服务。

例如：

```ts
export const inject = ['llm']

export function apply(ctx: Context) {
  ctx.llm.generate(...)
}
```

Cordis 会据此做三件重要的事：

1. **控制启动时机**

   如果 `llm` 还没有注册，消费者插件不会执行 `apply()`，其 Fiber 保持 `PENDING`。

   等 `llm` 出现后，消费者才启动。因此配置文件中两个插件的先后顺序通常并不重要。

2. **允许并约束服务访问**

   消费插件的 Fiber 会记录自己依赖了 `llm`。读取 `ctx.llm` 时，Proxy 根据这个依赖声明解析服务。

   在普通插件里，如果没有声明 `inject` 却直接访问某个服务，Cordis 通常会报告类似：

   ```text
   cannot get property "llm" without inject
   ```

3. **建立生命周期联动**

   如果提供 `llm` 的插件被卸载或热替换，依赖它的插件也会暂时卸载，清理监听器、定时器等副作用。

   当新的 `llm` 服务重新出现后，消费者会重新启动。它不是只在启动时检查一次依赖。[Cordis 服务教程](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cordis-tutorial/03-services.md)

还要区分 TypeScript 类型和运行时：

```ts
declare module '@deepseek-ai/cordis' {
  interface Context {
    llm: LLMService
  }
}
```

这段声明合并只负责让 `ctx.llm` 通过 TypeScript 类型检查，不会注册服务。

所以三者分工是：

```ts
super(ctx, 'llm')  // 运行时：提供服务
inject: ['llm']    // 运行时：声明硬依赖、控制生命周期和访问
Context { llm: … } // 编译时：提供 TypeScript 类型
```
