核心是两件彼此独立、但配合使用的事：

- `super(ctx, 'llm')`：注册服务
- `inject: ['llm']`：声明依赖

`ctx.llm` 则是从服务注册表里查出来的。

### 1. `super(ctx, 'llm')` 做了什么

假设插件定义了：

```ts
class LLMService extends Service {
  constructor(ctx: Context) {
    super(ctx, 'llm')
  }
}
```

调用 `super()` 后，会执行 `Service` 构造器中的：

```ts
self.ctx.reflect.provide(name, self, ...)
```

这里大致等价于：

```ts
ctx 的服务注册表.set('llm', 当前的 LLMService 实例)
```

所以建立的是这个映射：

```text
"llm" ──> LLMService 实例
```

它并不一定真的执行：

```ts
ctx.llm = self
```

因为 `Context` 是一个 `Proxy`。[source.md](/private/var/folders/sz/cc03_p510f55yvxmgytgww9r0000gn/T/xunxun-v2-7s8tqv_1/work/dsh-service-lifecycle/source.md:24) 当代码读取：

```ts
ctx.llm
```

Proxy 的属性读取逻辑会把属性名 `"llm"` 交给服务解析器，再从注册表中找到那个实例。

概念上类似：

```ts
const ctx = new Proxy(target, {
  get(target, key) {
    return serviceRegistry.get(key)
  },
})
```

因此完整链路是：

```text
super(ctx, "llm")
        │
        ▼
注册表保存 "llm" → 当前服务实例
        │
        ▼
其他代码读取 ctx.llm
        │
        ▼
Context Proxy 截获属性读取
        │
        ▼
服务解析器查找 "llm"
        │
        ▼
返回 LLMService 实例
```

### 2. `inject: ['llm']` 做了什么

例如：

```ts
export const inject = ['llm']

export function apply(ctx: Context) {
  ctx.llm.generate(...)
}
```

`inject` 的意思是：

> 这个插件的运行依赖名为 `llm` 的服务。

它不会把字符串 `"llm"` 转成对象，也不是类似下面的变量赋值：

```ts
const llm = resolve('llm')
```

实际对象仍然通过：

```ts
ctx.llm
```

取得。

`inject` 主要把依赖关系告诉 Cordis，让当前插件对应的 Fiber 管理这项依赖。根据 `source.md`，Fiber 负责插件的依赖状态、生命周期副作用和清理。[source.md](/private/var/folders/sz/cc03_p510f55yvxmgytgww9r0000gn/T/xunxun-v2-7s8tqv_1/work/dsh-service-lifecycle/source.md:24)

可以把它理解成：

```text
提供方：
super(ctx, "llm")
→ “我提供 llm 服务”

使用方：
inject: ["llm"]
→ “我必须依赖 llm 服务”

运行时：
ctx.llm
→ “现在把 llm 服务实例取出来”
```

所以三者的职责不同：

| 代码 | 作用 |
|---|---|
| `super(ctx, 'llm')` | 将当前实例注册为 `llm` 服务 |
| `inject: ['llm']` | 声明当前插件依赖 `llm` |
| `ctx.llm` | 在运行时解析并取得 `llm` 实例 |

最容易混淆的一点是：**让 `ctx.llm` 能返回对象的是 `provide()` 加上 Context Proxy；`inject` 负责依赖和生命周期管理，不负责创建这个属性。**
