不是一回事。它们都能“扩展 Pi”，但作用层级不同：

| 机制 | 本质 | 能否可靠拦截危险命令 |
|---|---|---|
| Extension | 在宿主进程中运行的 TypeScript 代码，可监听生命周期、注册或拦截工具 | **可以在 Pi 的工具执行入口强制阻断** |
| Skill | 提供给模型的 Markdown 操作说明 | 不可靠，只是在指导模型 |
| Prompt template | 展开成用户选择的提示文本 | 不可靠，同样只是提示模型 |

如果要真正拦住危险命令，选 **Extension**。应在工具实际执行前检查命令，命中规则就拒绝执行，而不是仅告诉模型“不要运行”。Skill 和 prompt template 都可能因为误判、上下文冲突或提示注入而失效，不能当安全边界。

但 Extension 也只保护它覆盖的执行路径。比较稳妥的设计是：

- 拦截所有能启动进程或修改系统的工具，而不只是常见的 shell 工具。
- 对命令进行结构化解析，避免简单字符串匹配被引号、变量、管道或编码绕过。
- 高风险操作默认拒绝，或要求人工确认。
- 检查异常时采用 fail-closed，也就是检查器出错便不执行。
- 记录允许、拒绝和审批事件。
- 再配合容器、文件系统权限、网络限制等 OS 级沙箱。

因此结论是：**Skill 可以解释安全政策，prompt template 可以方便用户套用政策，Extension 负责执行期强制；真正的硬安全边界还应放在 Pi 之外的系统权限或沙箱层。**
