不是一回事。它们都能“扩展 Pi”，但工作层级不同：

| 类型 | 本质 | 能力 | 能否可靠拦截危险命令 |
|---|---|---|---|
| **Extension** | 在宿主进程中运行的 TypeScript 模块 | 监听生命周期、注册或拦截工具、添加命令/UI、写入 session | **能** |
| **Skill** | 提供给模型的 Markdown 指令 | 教模型遵循某套流程或判断规则 | 不能保证 |
| **Prompt template** | 展开成用户提示词的文本模板 | 快速复用常见请求或上下文 | 不能保证 |

如果目标是“真正拦住危险命令”，应该选 **Extension**，在工具执行前拦截 `bash`/shell 工具调用，检查命令并拒绝执行。例如针对 `rm -rf`、危险的 `git reset --hard`、写入敏感路径等返回阻止结果。

关键区别是：

- Skill 和 prompt template 都只是进入模型上下文的文字，属于“劝模型不要做”。模型可能误判，指令也可能受上下文、压缩或冲突影响。
- Extension 是运行时的执行边界，可以在命令实际交给工具之前强制阻断，属于策略执行机制。
- Extension 自身拥有宿主进程权限，因此必须把它当安全敏感代码审查；同时应采用默认拒绝、命令解析、明确白名单等设计，避免只用容易绕过的字符串匹配。

简而言之：**Skill 负责教，prompt template 负责预填，Extension 才能执法。** 这些定义来自当前目录的 [source.md](/private/var/folders/sz/cc03_p510f55yvxmgytgww9r0000gn/T/xunxun-v2-c5rsc611/work/pi-extension-skill-template/source.md)。
