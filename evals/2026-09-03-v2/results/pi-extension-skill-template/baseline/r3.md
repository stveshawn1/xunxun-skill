不是一回事，只是都叫“扩展 Pi”。根据 [source.md](/private/var/folders/sz/cc03_p510f55yvxmgytgww9r0000gn/T/xunxun-v2-c5rsc611/work/pi-extension-skill-template/source.md)，它们位于不同层级：

| 机制 | 本质 | 能力 | 能否强制拦截 |
|---|---|---|---|
| Extension | 运行在宿主进程中的 TypeScript 代码 | 监听生命周期、注册或拦截工具、添加命令和 UI | **能** |
| Skill | 提供给模型的 Markdown 指令 | 教模型如何判断和操作 | 不能保证 |
| Prompt template | 展开成用户选择的一段提示词 | 快速复用任务模板 | 不能保证 |

如果要真正拦住危险命令，应选 **Extension**，在工具实际执行之前检查调用参数并拒绝或要求确认。

Skill 和 prompt template 都只是影响模型的文字。模型可能误判、遗漏、受上下文影响，甚至通过另一条执行路径绕过它们，因此只能作为“软约束”。

比较可靠的设计是：

1. Extension 负责硬拦截。
2. 默认拒绝明确危险的操作，并对高风险操作要求人工确认。
3. 检查所有能产生副作用的工具，而不只是命令名称；例如 shell、自定义文件工具和间接执行脚本。
4. Skill 负责告诉模型安全规范和替代做法，改善体验，但不作为安全边界。
5. 对特别高风险的环境，再叠加操作系统沙箱、容器或最小权限。Extension 本身拥有宿主进程权限，不等同于安全沙箱。

一句话：**Skill 和 prompt template 是劝模型别做；Extension 才能在执行入口说“不准做”。**
