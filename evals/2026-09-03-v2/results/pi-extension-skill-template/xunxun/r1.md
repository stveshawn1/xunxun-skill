不是一回事。它们都能“扩展 Pi”，但作用在不同层：

| 机制 | 本质 | 何时生效 | 能否强制拦截 |
|---|---|---|---|
| Prompt template | 一段可复用的用户提示词 | 发送给模型前展开 | 不能 |
| Skill | 提供给模型的 Markdown 操作说明 | 模型判断和规划时 | 不能可靠保证 |
| Extension | 在宿主进程里运行的 TypeScript 代码 | 工具调用、生命周期事件等运行时环节 | 可以 |

关键区别是：Skill 和 prompt template 都处于“告诉模型应该怎么做”这一层；Extension 则能进入实际执行路径。`source.md` 也明确区分了这三者：[source.md:26](/private/var/folders/sz/cc03_p510f55yvxmgytgww9r0000gn/T/xunxun-v2-c5rsc611/work/pi-extension-skill-template/source.md:26)。

可以这样理解：

- Prompt template：用户主动展开的“预制提问”。适合固定工作流入口，例如 `/review` 展开为一段代码审查要求。
- Skill：给模型看的“操作手册”。适合教它如何部署、审查或排错。它会影响模型决策，但最终仍由模型遵守。
- Extension：Pi 进程里的“程序插件”。它可以注册或拦截工具调用，因此能在命令真正执行前运行确定性的检查。

所以，要真正拦住危险命令，选 **Extension**。典型执行路径应当是：

```text
模型请求执行命令
        ↓
Extension 拦截工具调用
        ↓
解析并检查实际命令
   ↙          ↘
允许          拒绝
 ↓             ↓
执行       返回错误/要求确认
```

不过“Extension 可以拦截”不自动等于“绝对安全”。实现时还要满足：

- 检查发生在执行之前，而不是执行后的事件通知。
- 所有命令执行入口都必须经过拦截点，不能只保护一个命令工具而遗漏其他工具或扩展。
- 默认拒绝无法可靠解析的命令；单纯搜索 `rm` 字符串很容易被 shell 包装、脚本或子进程绕过。
- Extension 自己拥有宿主进程权限，因此必须把它当作可信代码审计。
- 真正的最终安全边界最好仍由操作系统沙箱、容器、文件权限和网络权限提供。

最实用的组合是：**Extension 做强制拦截，Skill 解释安全策略和替代做法，prompt template 提供方便的安全工作流入口。** 三者可以配合，但只有 Extension 位于适合执行强制策略的运行时层。
