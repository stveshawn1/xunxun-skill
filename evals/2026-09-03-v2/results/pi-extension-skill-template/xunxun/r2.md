不是一回事。它们都能“扩展 Pi”，但作用层级不同：

| 机制 | 本质 | 约束强度 | 适合做什么 |
|---|---|---:|---|
| Prompt template | 展开成一段用户提示词 | 最弱 | 复用任务模板 |
| Skill | 提供给模型的 Markdown 指令 | 软约束 | 教模型遵循某套流程、规范或知识 |
| Extension | 在宿主进程中执行的 TypeScript 代码 | 硬约束能力 | 拦截工具、拒绝操作、增加命令和 UI |

关键区别是：

- Prompt template 改变“这次对模型说什么”。
- Skill 改变“模型被指导成怎样做”。
- Extension 能改变“系统实际上允许发生什么”。

如果要真正拦住危险命令，应选 **Extension**。因为它可以在 shell 工具真正执行之前拦截调用，检查命令并拒绝执行；Skill 和 prompt template 都依赖模型配合，模型误解、遗漏或被其他指令影响时，危险命令仍可能被发出。[依据见 source.md](/private/var/folders/sz/cc03_p510f55yvxmgytgww9r0000gn/T/xunxun-v2-c5rsc611/work/pi-extension-skill-template/source.md:26)

可以这样记：

```text
Prompt template：帮模型开题
Skill：告诉模型应该怎么做
Extension：决定系统准不准它做
```

不过 Extension 的“硬”有明确边界：

1. 必须拦截所有能够执行命令的工具入口，而不只是某一个工具。
2. 只能管到经过 Pi 的调用；用户在 Pi 外面的终端操作不受它控制。
3. Extension 自身拥有宿主进程权限，因此它也是高信任代码，需要审查。
4. 真正可靠的安全方案最好再叠加 OS 沙箱、容器、低权限用户或审批机制。Extension 是 Pi 内的策略执行点，不应被当成唯一安全边界。

实际设计通常是：**Extension 负责强制拦截，Skill 负责让模型提前避免触发拦截，prompt template 负责提供具体任务入口。**
