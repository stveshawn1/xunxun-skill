不是一回事。它们都能“扩展 Pi”，但处在不同层级：

| 机制 | 本质 | 能做什么 | 能否可靠拦截危险命令 |
|---|---|---|---|
| Extension | 在宿主进程中运行的 TypeScript 程序 | 监听生命周期、注册或拦截工具、执行逻辑、显示 UI | **可以作为强制拦截点** |
| Skill | 提供给模型的 Markdown 指令 | 告诉模型应该如何判断和行动 | 不能保证；模型可能误判或不遵循 |
| Prompt template | 展开成用户提示词的文本模板 | 快速填入一段预设请求 | 更不能保证，只影响当次提示 |

关键区别是：

> Skill 和 prompt template 改变“模型想做什么”；Extension 可以控制“系统允许它做什么”。

所以，如果你要真正拦住 `rm -rf`、危险的 `git reset --hard`、向敏感路径写入等命令，应选 **Extension**，在命令实际执行前检查工具调用，并拒绝、改写或要求人工确认。

不过，Extension 的保护只有在以下条件成立时才完整：

- 所有 shell 命令都必须经过它所拦截的执行工具。
- 自定义工具、别名或其他执行通道也必须纳入检查。
- Extension 自身必须可信，因为它拥有宿主进程权限。
- 更高安全要求下，还应叠加操作系统沙箱、容器、文件权限或审批机制；Extension 不应是唯一边界。

一个实用组合是：

- **Extension**：强制执行安全策略。
- **Skill**：让模型提前识别风险、少触发拦截，并解释为何需要确认。
- **Prompt template**：方便用户启动某类固定工作流。
