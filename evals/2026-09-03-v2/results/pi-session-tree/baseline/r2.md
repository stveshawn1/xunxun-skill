对，JSONL 在物理上仍然只是一行一行追加。Pi 的“分叉”是通过每行里的 `id` 和 `parentId` 实现的：文件是线性的日志，里面记录的数据关系却是一棵树。

例如文件依次追加：

```jsonl
{"type":"message","id":"A","parentId":null,"role":"user","content":"你好"}
{"type":"message","id":"B","parentId":"A","role":"assistant","content":"你好！"}
{"type":"message","id":"C","parentId":"B","role":"user","content":"方案一"}
{"type":"message","id":"D","parentId":"C","role":"assistant","content":"回答一"}
{"type":"message","id":"E","parentId":"B","role":"user","content":"换个方向，方案二"}
{"type":"message","id":"F","parentId":"E","role":"assistant","content":"回答二"}
```

虽然物理顺序是：

```text
A → B → C → D → E → F
```

逻辑关系却是：

```text
A
└── B
    ├── C
    │   └── D
    └── E
        └── F
```

关键在于 `E.parentId` 是 `B`，而不是物理上一行的 `D`。也就是说，当你从旧节点 `B` 分叉时，Pi 不需要回到文件中间插入或修改内容，只需在文件末尾追加一个“父节点是 B”的新条目。

选择不同叶节点时，Pi 沿 `parentId` 向上追溯：

- 选择 `D`：得到 `A → B → C → D`
- 选择 `F`：得到 `A → B → E → F`

所以可以把它理解为：

> JSONL 决定记录怎么存；`parentId` 决定对话怎么连。

文件末尾的最后一行只是“最后写入的节点”，不一定是前一行的后续，也不等于唯一的当前对话。当前分支实际上由“选中了哪个叶节点”决定。
