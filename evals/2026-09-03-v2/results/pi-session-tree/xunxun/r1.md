对，JSONL 在物理上确实只能一行一行追加。Pi 的“分叉”不是把文件分成两段，而是通过每行里的 `id` 和 `parentId`，在同一个追加日志里表达一棵树。

例如文件按时间依次写入：

```jsonl
{"type":"session","id":"root"}
{"type":"message","id":"A","parentId":null,"text":"用户问题"}
{"type":"message","id":"B","parentId":"A","text":"回答 1"}
{"type":"message","id":"C","parentId":"B","text":"继续追问"}
{"type":"message","id":"D","parentId":"A","text":"从 A 重新回答"}
```

物理顺序永远是：

```text
A → B → C → D
```

但 `parentId` 表达的逻辑结构是：

```text
A
├── B
│   └── C
└── D
```

关键在于，追加的新行不必把“文件最后一行”作为父节点。

当你回到 `A` 创建分支时，Pi 不修改或删除 `B`、`C`，只是继续在文件末尾追加 `D`，并让：

```json
"parentId": "A"
```

之后加载会话时，Pi 选择一个叶子节点，然后沿着 `parentId` 反向追溯祖先：

- 选择 `C`：加载 `A → B → C`
- 选择 `D`：加载 `A → D`
- 不会简单地把文件中所有行都塞进上下文

所以可以把它理解为：

> JSONL 的行序负责记录“事件何时写入”，`parentId` 负责记录“事件属于哪条对话路径”。

这和 Git 很像：Git 对象可以不断增加，但每个 commit 通过父指针组成不同分支。Pi 所说的“同一个文件里分叉”，分叉的是逻辑上的会话树，不是 JSONL 文件本身的字节结构。`source.md` 里的 “selected leaf’s ancestry” 指的正是：从当前选中的末端节点，顺着父指针取回它的祖先链。
