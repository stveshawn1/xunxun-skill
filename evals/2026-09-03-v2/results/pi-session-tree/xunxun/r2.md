对，JSONL 在物理上确实只能一行一行追加。Pi 的“分叉”不是把文件分成两段，而是通过每行里的 `id` 和 `parentId`，在逻辑上组成一棵树。

例如文件仍按这个顺序写入：

```jsonl
{"id":"A","parentId":null,"message":"你好"}
{"id":"B","parentId":"A","message":"回答 1"}
{"id":"C","parentId":"B","message":"继续聊"}
{"id":"D","parentId":"B","message":"换个方向"}
```

物理顺序是一条直线：

```text
A → B → C → D
```

但 `parentId` 表达的逻辑关系是：

```text
A
└─ B
   ├─ C
   └─ D
```

因此：

- 选择 `C` 作为叶子，Pi 沿 `parentId` 向前追溯，得到 `A → B → C`
- 选择 `D` 作为叶子，得到 `A → B → D`
- `C` 虽然在文件中位于 `D` 前面，却不会进入 `D` 这条对话上下文

也就是说，Pi 新建分支时不需要回到文件中间插入或修改内容，只需在文件末尾追加一个新条目，让它的 `parentId` 指向较早的节点。

可以把 JSONL 理解成“所有节点的追加式仓库”，而不是“当前对话的逐字稿”。文件行序负责记录写入顺序，`parentId` 负责记录对话结构。加载时选择某个叶节点，再沿祖先链重建当前对话。[source.md](</private/var/folders/sz/cc03_p510f55yvxmgytgww9r0000gn/T/xunxun-v2-7s8tqv_1/work/pi-session-tree/source.md:8>) 里的 “follows the selected leaf's ancestry” 指的正是这个过程。
