对，JSONL 在物理上确实只能一行一行追加。Pi 的“分叉”不是把文件分叉，而是让文件里的记录组成一棵树。

关键就在每条记录的两个字段：

```ts
id: string
parentId: string | null
```

例如文件仍然按顺序追加：

```jsonl
{"id":"A","parentId":null,"message":"你好"}
{"id":"B","parentId":"A","message":"你好，有什么需要？"}
{"id":"C","parentId":"B","message":"解释 JSONL"}
{"id":"D","parentId":"C","message":"……原回答……"}
{"id":"E","parentId":"B","message":"解释 session tree"}
{"id":"F","parentId":"E","message":"……新回答……"}
```

物理存储顺序是一条线：

```text
A → B → C → D → E → F
```

但 `parentId` 表达的逻辑结构是：

```text
A
└── B
    ├── C
    │   └── D
    └── E
        └── F
```

因此加载某个对话时，Pi 不会把文件里的全部行都塞进上下文，而是：

1. 选择一个叶子节点；
2. 沿着它的 `parentId` 一直向上追溯；
3. 将这条祖先链还原成当前对话。

选择 `D`，得到：

```text
A → B → C → D
```

选择 `F`，得到：

```text
A → B → E → F
```

所以更准确地说：

> JSONL 的追加顺序负责保存“事件何时写入”，`parentId` 负责表达“事件属于哪条对话路径”。

这和 Git 很像：Git 对象也可以不断增加，但每个 commit 指向自己的父 commit，所以同一套对象中能存在多个分支。Pi 只是把类似的父指针结构放进了一个 JSONL 日志里。
