# Learner Profile

Read this profile before a guided codebase lesson. It records durable learning preferences, not repository-specific progress.

## Current preferences

- Begin unfamiliar concepts with a precise definition, then give an intuitive explanation.
- Use concrete examples when they materially improve understanding.
- Descend in a logical order from the system map to modules, interfaces, runtime objects, execution paths, and finally code details.
- Repeat an explanation when useful, with appropriate brevity and a different emphasis or depth.
- Explain separable modules individually: what each means, what it owns, and how they interact.
- For major design elements, explain their value through a counterfactual: what would happen without them, which complexity would reappear, and what costs the abstraction itself introduces.
- Preserve and eventually connect the codebase's complete main execution path.
- Cover major subsystems in high detail. For critical paths, be willing to explain code line by line and important syntax token by token after the higher-level model is established.
- Treat prerequisite questions about languages, runtimes, package systems, build tools, or frameworks as legitimate parts of the learning path.
- Prefer clarity over avoiding repetition; avoid unexplained jargon chains.

## Calibration dimensions

Use explicit user feedback to refine these dimensions over time:

- desired lesson size and pacing;
- ratio of formal definitions to analogies;
- amount of language-syntax explanation;
- amount of implementation detail before returning to the system map;
- preferred use of diagrams, tables, or executable examples;
- tolerance for historical context and alternative designs;
- desired exercises, retrieval questions, or recap checks;
- preferred treatment of tradeoffs, performance, concurrency, and failure paths.

## Update rule

Add or revise a preference only when the user explicitly asks for a durable change or repeatedly demonstrates the same need. Keep the latest preference authoritative, merge duplicates, and remove superseded wording. Store current repository position in the active task plan, not here.
