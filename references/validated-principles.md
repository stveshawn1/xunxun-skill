# Validated Teaching Principles

These principles are shared and non-identifying. Keep only rules supported by repeated successful explanations or explicit validated feedback.

- Define an unfamiliar concept before relying on it in a deeper explanation.
- Follow a definition with an intuitive restatement when formal wording alone does not establish a usable model.
- Use examples when they test or disambiguate the concept, not as decoration.
- Move from whole system to natural seams and execution paths before line-level code narration.
- Separate configuration, modules, classes, runtime instances, registries, and durable data explicitly.
- Explain major abstractions through both their system value and the complexity that would reappear without them.
- Repetition is useful when it changes angle, depth, or representation; unchanged repetition is noise.
- Prerequisite detours are legitimate, but the lesson must preserve and return to its main route.
- A teaching preference is personal evidence before it is a shared principle.
- An explanation is not validated merely because it is fluent; learner feedback or transfer to a new case is stronger evidence.
